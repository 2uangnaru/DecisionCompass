## What each file needs, in words

### `pubspec.yaml`

1. `flutter_localizations` from the SDK, and `intl: any`, under `dependencies`.
   Both ship with Flutter; no third-party or network translation service.
2. `generate: true` under `flutter:`, which is what makes `flutter pub get`
   run `gen_l10n` over `lib/l10n/*.arb` into `lib/l10n/app_localizations*.dart`.
3. Five bundled font families under `flutter: fonts:` — `NotoSans`,
   `NotoSansThai`, `NotoSansDevanagari`, `NotoSansJP`, `NotoSansSC`, each with
   a Regular and a `weight: 700` Bold from `assets/fonts/`.
4. Two licence files under `flutter: assets:` —
   `assets/fonts/OFL-NotoSans.txt` and `assets/fonts/OFL-NotoSansCJK.txt`.
   The whole `assets/fonts/` directory is deliberately **not** listed: that
   would bundle the 27 MB of font binaries a second time as plain assets.

Codex's own `assets/` entries are independent of these and can be added
alongside.

### `lib/theme.dart`

`buildCompassTheme()` takes an optional `AppLocale` (defaulting to English, so
every existing call site still compiles) and uses it for two things only:

- `fontFamily` / `fontFamilyFallback` from the new `CompassFonts.fallbackFor`,
  which puts the reader's own script first. The order matters for Han: Japanese
  and Simplified Chinese share thousands of codepoints and draw some of them
  differently, so whichever family comes first decides the shape.
- A `lead` multiplier on the text theme's line heights — 1.22 for Thai and
  Devanagari, 1.12 for Japanese and Chinese, 1.0 for the Latin-script
  languages. Thai vowel and tone marks stack above and below the line and
  Devanagari hangs conjuncts below it; they clip at the English line heights.
  Nothing is shrunk to compensate.

Colours, sizes, shapes and every other theme value are identical across
languages, so no locale gets a quietly different design.

### `lib/main.dart`

1. `main` is now `Future<void>` and calls `WidgetsFlutterBinding.ensureInitialized()`.
2. `await initializeDateFormatting()` from `package:intl/date_symbol_data_local.dart`,
   so `DateFormat` has patterns for all seven locales. Compiled in; no network.
3. Builds a `LocaleController(store: SharedPreferencesLocaleStore())` and
   **awaits `ensureLoaded()` before `runApp`**. That await is what stops a
   reader who chose Thai from watching English paint first.
4. Passes that controller to `ReadingDependencies(localeController: …)`.
5. `_registerFontLicenses()` yields the two bundled SIL OFL texts into
   `LicenseRegistry`, so the licence shows up in Flutter's own licence list.

### `lib/app.dart`

1. `compassLocalizationsDelegates` and `compassSupportedLocales` are exported
   as top-level values, because the tests that mount a single page need the
   exact same localizations the app installs.
2. `build` wraps `MaterialApp` in a `ListenableBuilder` on
   `dependencies.localeController`, so one notification re-renders the whole
   app — welcome screen, onboarding, date and time pickers, safety sheet and
   Home together, with no screen left in the previous language.
3. `MaterialApp` gains `locale`, `localizationsDelegates`, `supportedLocales`,
   `onGenerateTitle`, and a `localeListResolutionCallback` that returns the
   chosen locale unconditionally. That callback is the rule "a phone's
   country, location or timezone never selects a language" expressed in code.
4. `_VerifiedCountryNames` wraps `country_picker`'s delegate and reports
   support only for `en`, `es`, `ja`, `zh`. Two reasons, both deliberate:
   - the package answers `hi` with its **Nepali** country list, and presenting
     Nepali as Hindi is worse than a visible English fallback;
   - its own `load` returns a plain `Future`, which makes `Localizations`
     resolve over an extra frame and shows an empty screen before the first
     real paint. The wrapper returns a `SynchronousFuture` instead.

   Vietnamese and Thai have no country list in the package at all. All three
   gaps are recorded in `MISSING_KEYS.md`.

#### One known consequence

Because `_VerifiedCountryNames` reports support for only four of the seven
locales, Flutter prints a debug-mode warning on each switch to `vi`, `th` or
`hi-IN`:

> This application's locale, th, is not supported by all of its localization
> delegates.

That warning is the missing country-name list, stated accurately. It does not
appear in a release build. It can be removed without losing the guarantee by
reporting support for all seven and returning a `CountryLocalizations`
subclass whose `countryName` returns `null` for the three unverified locales —
that keeps English country names and still refuses to show Nepali as Hindi.
Claude did not make that change because `app.dart` was frozen.

If Codex would rather not carry item 2, the `ListenableBuilder` can be replaced
by any other rebuild mechanism, but the whole subtree below `MaterialApp` must
rebuild when the language changes — rebuilding only the current page leaves the
pickers and the safety sheet behind.
